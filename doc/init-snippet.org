#+title: org-agents: init.org snippet
#+startup: showall

One =use-package= block, written in the style of the surrounding Org
extensions in =~/org/init.org=, plus a first agent to try it on.

*Where it goes.* Under =*** org-ql= (line 11513 today), immediately after
=**** org-ql-semantic= (which ends at line 11592), as one more level-four
sibling. That is the right neighbourhood: =org-agents= requires =org-ql= and
=org-ql-ext=, whose =property-ts= predicate is the one the examples below
lean on.

One thing about that neighbourhood is worth saying out loud: an agent query
may NOT use =(semantic "...")=. org-ql compiles that predicate by running
its normalizer, which spawns =org db search= past the evaluation gate, so
=org-agents-refused-heads= ships refusing it and the query signals instead
of running. Semantic search stays available as =M-s s=; see the option's
comment in the block below for how to accept the subprocess instead.

One thing is not turned on for you: completion of declared attribute
values. It is a function on Org's own
=org-property-allowed-value-functions=, and a library has no business
adding itself to a user's hook at load time, so the =:init= =add-hook= in
the block below is what arms it. Point =org-agents-attributes-file= at the
Org file that declares your attributes — the default is
=~/org/attributes.org=, and one that is not there declares nothing and says
nothing about it. =doc/attributes-example.org= is a whole one, written out.

That same file carries the prototypes. A reserved top-level =* Prototypes=
section holds master entries, and any entry in the corpus reads through one
by naming it in =:PROTOTYPE:= — by name, or by =id:UUID= for a master that
lives out in the corpus instead. Prototypes add NO option of their own, and
no command and no hook was added for them.

That same file's =:ATTR_FACES:= is what =org-agents-faces-mode= draws with: a
headline whose RESOLVED value for a declared attribute is one that attribute
maps to a face is drawn in that face. Off until asked for, in either of the
two ways below, and it writes NOTHING — one font-lock keyword, no text, no
property, no overlay.

Actions are the one feature here that WRITES to the corpus, and nothing about
them is turned on either — not in the sense the two paragraphs above use
that phrase, but in a stronger one: there is nothing to turn on. One option
and one command is the whole of it. =org-agents-apply-actions= exists and
does absolutely nothing at all until it is typed: no hook, no timer, no save
and no =org-agents-update= integration reaches it, and a file whose agent
carries an =:AGENT_ACTION:= saves exactly as one without it renders. The
option is =org-agents-action-limit=, which bounds how many entries ONE run
may edit; it is risky, so no file can raise it, and its default of 100 is
chosen so that a mistake stays reviewable rather than for speed. The last
section below has a first action to try and what its dry run prints.

The =id:= spelling does lean on one setting that already exists: it resolves
through =org-id='s location table, so =org-id= must know which file holds the
master (=org-id-track-globally= on and a populated =org-id-locations-file=, or
the master in the follower's own file). Otherwise the reference dangles with
a one-line diagnostic. Naming a master by =name= needs nothing but the file
above.

There is nothing else that must be configured. The candidate-file
prefilter is ripgrep, which needs no DSN, no config file and no
credential: it is found on =exec-path= or it is not, and where it is not
an unbounded scope is scanned live with one message saying so. Two options
govern it if you want them — see the block below.

* Paste-ready block

**** org-agents

Agents in the sense of Eastgate Tinderbox: an ordinary Org entry carrying an
org-ql query in =:AGENT_QUERY:=, which on update populates itself with links
to every entry that matches — as child alias headings, as a plain list, or
as a table. Queries are org-ql S-expressions with a =$PROP= layer on top, so
=$NEXT_REVIEW= reads as the property name, the value, or a number, according
to the position it appears in.

#+begin_src emacs-lisp
(use-package org-agents
  :after (org-ql-ext)
  :commands (org-agents-update
             org-agents-update-buffer
             org-agents-update-all
             org-agents-apply-actions
             org-agents-preview
             org-agents-insert-dblock
             org-agents-list-approvals
             org-agents-check-attributes
             org-agents-attribute-columns
             org-agents-mode
             global-org-agents-mode
             org-agents-faces-mode
             global-org-agents-faces-mode)
  ;; Org calls the dynamic-block writer by name, from C-c C-x C-u and from
  ;; `org-update-all-dblocks', so it has to be autoloaded as well.
  :autoload (org-dblock-write:org-agents
             org-agents-allowed-values)
  :init
  ;; What arms completion of declared attribute values.  The package does
  ;; not add itself to this hook -- it is Org's, and it is the user's.
  ;; Spelled as an `:init' `add-hook' and not as `:hook', because
  ;; use-package appends `-hook' to a `:hook' name that does not already
  ;; end in it, and this one ends in `-functions'.  The symbol is
  ;; autoloaded, so the package still loads on first use and not at
  ;; startup: nothing runs until Org asks for a property's allowed values.
  (add-hook 'org-property-allowed-value-functions
            #'org-agents-allowed-values)
  :bind
  (("M-s a" . org-agents-preview)
   :map
   org-mode-map
   ("C-c C-x Q" . org-agents-update)
   :map
   my-ctrl-c-n-map
   ("u" . org-agents-update-buffer)
   ("U" . org-agents-update-all))
  :custom
  ;; The Org file declaring this corpus's own attributes -- ATTR_TYPE,
  ;; ATTR_VALUES, ATTR_DEFAULT per top-level entry -- and, under one
  ;; reserved `* Prototypes' heading, the master entries that
  ;; `:PROTOTYPE:' names.  Pure data; nothing in it is ever evaluated.
  ;; Optional: one that is not there declares nothing, names no prototype,
  ;; and says nothing about either, and the package never creates it.
  ;; doc/attributes-example.org is a whole one, written out.  Named here
  ;; rather than left at the default only because ~/org is where it
  ;; belongs on this machine and `org-file' is what spells that.
  (org-agents-attributes-file (org-file "attributes.org"))
  ;; How many entries one `org-agents-apply-actions' will edit.  Left at
  ;; its default of 100 deliberately: it is the ONE bound on how far an
  ;; action reaches, a plan over more than it is REFUSED rather than
  ;; truncated, and the number is chosen so that a mistake stays
  ;; reviewable -- 100 modified buffers can be read through and undone,
  ;; and three thousand cannot.  Raise it here, in the trusted zone, for
  ;; an agent that legitimately stamps a corpus; nothing in a file can.
  ;; (org-agents-action-limit 100)
  ;;
  ;; The other seven options are best left at their defaults:
  ;; `org-agents-exclude' — (not (property "AGENT_MATCH")) — is what keeps
  ;; agents from consuming each other's aliases;
  ;; `org-agents-safe-queries' grows by answering "remember this approval
  ;; permanently?" at the prompt, which writes to `custom-file'
  ;; (settings.el) — only a query holding Lisp outside the org-ql
  ;; vocabulary ever prompts, and every example below is structurally safe
  ;; and runs unremarked;
  ;; `org-agents-prefilter' is `auto', which narrows an unbounded scope
  ;; with ripgrep where it can and scans live with one message where it
  ;; cannot — set it to `require' to be refused rather than kept waiting,
  ;; or to nil never to spawn anything;
  ;; `org-agents-refused-heads' is `(semantic)', which is what makes
  ;; `(semantic "...")' in an agent query SIGNAL rather than run: org-ql
  ;; compiles that predicate by calling its normalizer, and the normalizer
  ;; spawns `org db search' after the gate has finished and whatever the
  ;; user answered — remove `semantic' from the list to accept that
  ;; subprocess, since no approval overrides a refusal;
  ;; `org-agents-refused-queries' is the negative twin of
  ;; `org-agents-safe-queries', written by pressing `r' in
  ;; `org-agents-list-approvals', which is also where an approval is read
  ;; back and revoked;
  ;; `org-agents-rg-executable' is "rg", resolved against
  ;; `exec-path' — name the binary here if ripgrep is installed under
  ;; another name, or somewhere a GUI Emacs's `exec-path' does not
  ;; reach;
  ;; and `org-agents-rg-timeout' is 30 seconds, which is the bound on how
  ;; long a prefilter run may take before it is abandoned and the scope is
  ;; scanned live instead — about 50× the slowest run measured over this
  ;; corpus, so an expiry means something is wrong rather than merely
  ;; slow.  An expiry costs a slow correct answer and never a wrong one.
  ;; Like the six above it, this is on the owned list and marked risky:
  ;; a file that could set it from its own local-variables block could set
  ;; it to nil, which takes the bound off entirely — the very defect the
  ;; bound removes — or to 0, which sends every corpus-scope agent down
  ;; the live whole-corpus walk.
  ;;
  ;; Where `org-agents-update-all' looks: files (each scanned for
  ;; `:AGENT_QUERY:') or directories, or the symbol `agenda'.
  (org-agents-files (list (org-file "agents.org")
                          org-constants-todo-path)))
#+end_src

* Updating on save

=org-agents-mode= updates a buffer's agents in =before-save-hook=, so an agent
is refreshed by the act of saving the file it lives in. A save whose render
changes nothing writes no bytes — old =AGENT_MATCHED= stamps and all — and a
save spawns no subprocess whatever =org-agents-prefilter= says. Agents whose
scope is =active=, =all= or a directory are named once and skipped: there is
no bound on what one of those would open, and a save is a keystroke. =C-c n
u= still refreshes them on demand.

*The lazy way, and the one to prefer here.* Arm just the files that hold
agents, with a file-local minor mode on the first line. Emacs appends the
=-mode= suffix itself, so the value is =org-agents= and not =org-agents-mode=;
being a =mode:= entry rather than an =eval:= one, it raises no risky-local
prompt, and visiting the file is what autoloads the package:

#+begin_example
# -*- mode: org; mode: org-agents; -*-
#+title: Agents
#+end_example

That suits the two files =org-agents-files= already names, and costs nothing
in any other Org buffer.

*The blanket way.* =global-org-agents-mode= arms every Org buffer whose text
mentions =:AGENT_QUERY:=, deciding that with a plain regexp so the check is
cheap enough to run on every Org buffer you visit. It has to be called to take
effect, which loads =org-agents= at startup rather than on first use — the
price of not having to mark each file:

#+begin_src emacs-lisp
(global-org-agents-mode 1)
#+end_src

* Appearance from attribute values

=org-agents-faces-mode= draws a headline in the face its attribute value maps
to. The value it reads is the RESOLVED one, so an entry spelling only
=:PROTOTYPE:= — or nothing at all, and taking =:ATTR_DEFAULT:= — is faced
exactly as one spelling the value in its own drawer. It CHANGES NO BYTES: one
font-lock keyword, nothing inserted, no property written, no overlay, and
turning it off restores the buffer exactly. So it is safe to leave on in
files under version control.

Declare the mapping in the registry beside the type:

#+begin_example
,* STATUS
:PROPERTIES:
:ATTR_TYPE:    string
:ATTR_VALUES:  active stalled done
:ATTR_DEFAULT: active
:ATTR_FACES:   active org-todo | stalled org-warning
:END:
#+end_example

*The lazy way.* A file-local minor mode on the first line of the files that
want it. Emacs appends the =-mode= suffix itself, so the value is
=org-agents-faces=; being a =mode:= entry it raises no risky-local prompt, and
visiting the file is what autoloads the package:

#+begin_example
# -*- mode: org; mode: org-agents-faces; -*-
#+title: Projects
#+end_example

*The blanket way.* =global-org-agents-faces-mode= arms EVERY Org buffer, and
deliberately not only those whose text mentions a property the way
=global-org-agents-mode= does: a value arriving through a prototype or a
default is spelled nowhere, so a text scan would miss exactly the entries
the mode exists for. Like the other globalized mode it has to be called to
take effect, which loads =org-agents= at startup rather than on first use.

#+begin_src emacs-lisp
(global-org-agents-faces-mode 1)
#+end_src

Both together are fine: enabling the mode twice in one buffer is a no-op, so
the file-local entry and the blanket mode can be in force at once.

Measured, that is affordable: where nothing declares a face the mode answers
before resolving anything at all, so a corpus with no registry pays a regexp
scan of the displayed region and nothing else. With a registry the cost is
what is on SCREEN — over a 400-entry buffer, a twelve-line window costs 3
resolutions where the whole buffer costs 400 under the one-attribute registry
above, and 5 against 799 under a registry declaring two faced attributes,
since each unmapped headline is resolved once per declaration — and the
registry is read once per fontified region rather than once per headline.

Editing =:STATUS:= in a drawer moves the face on the headline above it. An
edit to the REGISTRY, or to a prototype master in another buffer, does not
refontify the followers: an armed buffer left open across such an edit keeps
its old colour until it is refontified, by =M-x font-lock-flush= or by being
scrolled away and back.

=M-s a= sits deliberately beside =M-s s=: semantic search and agent preview are
the two ways of asking "what would match?" before committing anything to a
drawer. Preview is =org-ql-search= over the expanded query with the agent exclusion
appended, and it is the appended form that is gated, so what it shows is
what an agent would render.

No binding is needed for the dynamic block: Org's own =C-c C-x x= offers
=org-agents= as a block type once the package has loaded, and =C-c C-x C-u=
updates the block at point.

=org-agents-apply-actions= gets NO binding, and that is a choice rather than
an omission. It is the one command here that writes outside the file you are
looking at, and =my-ctrl-c-n-map= has =A= taken anyway; a command whose whole
value is that it only ever runs when somebody meant it does not want a
two-keystroke home next to the update commands. =M-x= is the right length for
it. Bind it later, if ever, once its dry run has stopped being the
interesting part.

* First agent

Put this in =~/org/agents.org= (which the =:custom= above registers), then
update it with =C-c C-x Q=. It uses the default =children= view and the default
=agenda= scope, so it searches the nine files in =org-agenda-files= and needs
no prefilter at all:

#+begin_example
* Reviews that have come due
:PROPERTIES:
:AGENT_QUERY:  (and (todo) (property-ts $NEXT_REVIEW :to today))
:AGENT_FORMAT: NEXT_REVIEW
:AGENT_SORT:   date
:AGENT_LIMIT:  25
:END:
#+end_example

After the update the entry has grown one child per match, and a status line
of its own:

#+begin_example
* Reviews that have come due
:PROPERTIES:
:AGENT_QUERY:   (and (todo) (property-ts $NEXT_REVIEW :to today))
:AGENT_FORMAT:  NEXT_REVIEW
:AGENT_SORT:    date
:AGENT_LIMIT:   25
:AGENT_MATCHED: 3 [2026-08-19 Wed 09:14]
:END:
** [[id:1F2E3D4C-...][Review: Renew the domain]] [2026-08-14 Fri]
:PROPERTIES:
:AGENT_MATCH: t
:END:
#+end_example

Those aliases are ephemeral: every update reaps the ones that hold nothing
but their drawer. Write anything under an alias and it is yours — no update
deletes it, and if its match is gone it is retitled =(stale)= instead.

*Matching through a prototype.* Where an entry inherits a value rather than
spelling it, =(property "STATUS" "wip")= does not match it and
=(property-resolved "STATUS" "wip")= does:

#+begin_example
,* Work in progress, wherever it says so
:PROPERTIES:
:AGENT_QUERY:  (and (todo) (property-resolved "STATUS" "wip"))
:AGENT_FORMAT: OWNER
:END:
#+end_example

=(and (todo) $STATUS^)= is NOT that query written short: =$STATUS^= expands
to =(property-resolved "STATUS")=, which asks whether =STATUS= resolves at
all rather than whether it resolves to =wip= — and where the registry
declares an =:ATTR_DEFAULT:= for the name, that is true of every entry. Write
the value out when you mean the value.

The =^= suffix is the prototype axis and the =*= suffix is the outline one —
=$STATUS*= is =org-entry-get= with inheritance, which is a different
question — and a reference carries at most one of them.

The whole property vocabulary implemented today: =AGENT_QUERY= (required),
=AGENT_VIEW= (=children= default, =list=, =table=), =AGENT_SCOPE= (=agenda= default,
=active=, =all=, a directory, or a list of files), =AGENT_SORT=, =AGENT_LIMIT=,
=AGENT_COLUMNS= (table), =AGENT_FORMAT= (=children= and =list=). =AGENT_MATCH= and
=AGENT_MATCHED= are written by the package, not by hand.

* A standalone dynamic block

A block with its own =:query= needs no agent entry around it at all, and can
go in any Org file. This one is a table; =C-c C-x C-u= on it renders it:

#+begin_example
#+BEGIN: org-agents :query (and (property "NEXT_REVIEW") (todo "TODO")) :view table :columns "ITEM_BY_ID NEXT_REVIEW LAST_REVIEW" :sort (ts-column 2) :limit 20
#+END:
#+end_example

=ITEM_BY_ID= is the link column, wherever in =:columns= it is named; every
other name is read as a property on the matched heading. =(ts-column 2)=
orders the rendered rows by the second column read as timestamps, and is
table-only — a =children= or =list= view says so rather than sorting nothing.
Written inside an agent entry instead, a block's parameters override that
entry's =AGENT_*= properties name by name, so one agent can carry several
views of itself.

* A first action

An agent may carry an =:AGENT_ACTION:= as well as a query: a declarative
sentence saying what to do to the entries the query matched. Nine verbs are
shipped — =set-property!=, =delete-property!=, =tag!=, =todo!=, =priority!=,
=scheduled!=, =deadline!=, =effort!=, =archive!= — and a tenth is a =defun= in
this same init file; see README's "Action code" for the whole reference.

Add a line to the review agent above and it can stamp what it finds:

#+begin_example
,* Reviews that have come due
:PROPERTIES:
:AGENT_QUERY:  (and (todo "TODO") (property-ts "NEXT_REVIEW" :to today))
:AGENT_ACTION: set-property!(REVIEWED, today) tag!(+reviewed)
:END:
#+end_example

Then =M-x org-agents-apply-actions= with point in that entry. It does NOT
edit anything: it prints one line per intended edit into =*Org Agents
Actions*= and stops. A real one, over two files with three matching entries:

#+begin_example
org-agents: 6 edits at 3 entries in 2 files (1 not open before this ran).  Nothing written yet.
/home/johnw/org/proj.org:1: set-property!(REVIEWED, today)  nil -> [2026-08-20 Thu]
/home/johnw/org/proj.org:1: tag!(+reviewed)  :api: -> :api:reviewed:
/home/johnw/org/proj.org:5: set-property!(REVIEWED, today)  nil -> [2026-08-20 Thu]
/home/johnw/org/proj.org:5: tag!(+reviewed)  :api: -> :api:reviewed:
/home/johnw/org/notes.org:1: set-property!(REVIEWED, today)  nil -> [2026-08-20 Thu]
/home/johnw/org/notes.org:1: tag!(+reviewed)  :api: -> :api:reviewed:
#+end_example

That buffer is =compilation-mode=, so =RET= and =M-g n= walk the edits before
any of them exists. One question follows — =apply 6 edits at 3 entries in
2 files (1 not open before this ran)?= — and answering =n= writes nothing at
all. Answering =y= applies them in order, writes the outcome onto each line,
names the buffers it modified, and SAVES NOTHING: the worst case of a wrong
action is a handful of modified buffers to read through and =undo=, one at a
time.

Two things about that are worth knowing before writing one.

=today= is a keyword and there are exactly three — =today=, =now=, =empty= —
so =set-property!(REVIEWED, today)= stores an inactive stamp rather than the
word. To store the word, quote it: =set-property!(REVIEWED, "today")=. A bare
word is literal unless it is one of those three; a quoted argument always is.

And =tag!= is NOT org-edna's. It takes SIGNED terms — =+reviewed= adds,
=-stale= removes — and refuses an unsigned one. Edna's =tag!= hands a whole
tag specification to =org-set-tags=, which REPLACES an entry's tags; over an
agent's match set that would be a silent mass deletion from a verb whose
one-word form looks additive.

=C-u M-x org-agents-apply-actions= is the same thing pointed at a selection:
the targets become the entries the links in the region name, and the action
text still comes from the agent's own drawer. That is how a stamp is spelled
here — mark four rows of a table view, then =C-u M-x
org-agents-apply-actions=. Point has to stay inside the agent's own entry,
which for a list or a table view is free, since the block is in the entry.

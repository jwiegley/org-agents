drawer carries ATTR_TYPE (string|number|date|boolean|set|list), ATTR_DEFAULT,

  modification tick, re-reading only when it changes.

  error; a malformed entry is reported once by name and skipped.
- Types validate values: a `date` default that does not parse is diagnosed at
  read time, not at first use.
- Tests: cache invalidation on edit; malformed entry skipped and named;
  absent file harmless.

## What is already done

The cost gate shipped. `org-agents--needs-prefilter-p` decides by SCOPE, not by
whether the query has something to push: `active`, `all` and a directory are
narrowed because nothing about them bounds what they hold; `agenda` and an
explicit file list name their files and are read live, where a prefilter is pure
overhead. Both halves are pinned —
`org-agents-test-prefilter-not-consulted-for-named-files` makes the spawn
DETECTABLE rather than assumed away (a `call-process` stub that records the
breach in a flag, because the backend catches errors by design and would swallow
a signalling stub), and `org-agents-test-prefilter-consulted-for-a-corpus-scope`

prefiltering at all.

Measured 2026-08-19, replacing this issue's original 0.018 s figure, which was
quoted as measured in four places by people who had not measured it: an
`agenda`-scope update over the eight largest files of the corpus — 8.9 MB, 373

ripgrep run over the corpus costs 0.10 to 0.45 s.

The defcustom file-count threshold this issue proposed was NOT implemented, and
is tracked separately as `orga-deferred-features-fbk.9`.

## What survives, and is the whole of this issue now

`org-agents--rg-run` is a synchronous `call-process` with no timeout, and the
argument vector passes `--follow`. So an unbounded scope whose root reaches a
slow or unresponsive filesystem through a followed symlink — an NFS or sshfs
mount, a sleeping external disk — blocks Emacs inside the prefilter for as long
as the filesystem takes. This is milder than the version this replaces: there is
no network protocol and no TCP timeout to wait out, and `C-g` escapes the
synchronous call (`org-agents--rg-run`'s docstring commits to that: a `quit`
during the call still escapes, as it must). But "the user can always interrupt
it" is not the same as "no code path blocks", and the original criterion asked
for the latter.

## Acceptance Criteria

- [x] an agenda-scope agent with a pushable conjunct spawns no subprocess, and a
      test asserts it
- [x] a corpus-scope agent still uses the prefilter, and a test asserts that too
- [ ] the prefilter cannot block Emacs for an unbounded time on an unresponsive
      filesystem: either `org-agents--rg-run` grows a timeout (which means
      `make-process` plus a sentinel, or `call-process` under an interrupt timer
      — `call-process` takes no timeout argument), or the decision to rely on
      `C-g` is written down as deliberate, with the reasoning, so it stops
      reading as an oversight
- [ ] whichever is chosen, a test covers it with a deliberately hanging stub

## Note on --follow

Dropping `--follow` would shrink the exposure and is NOT an option: the flag is
there because `directory-files-recursively` lists a symlink to a file outside the
tree and org-ql matches through it, so without it the candidate set would be
narrower than the scope's own file list — a lost match rather than a slow one.
See `org-agents--rg-args` and README's honest limitation 4.

Prefilter widening for property-resolved — the soundness rule.

An inheriting entry never spells the value, so the ordinary property pattern
under-matches (silent lost matches). Widening: a file containing a matching
entry either spells a local :NAME: line or carries a :PROTOTYPE: line, so
push the alternation `^[ \t]*:(NAME\+?|PROTOTYPE\+?):`.

EXCEPTION: when the tested value equals the registry ATTR_DEFAULT, or the
query is bare existence and a default is declared, an entry with neither line
also matches — nothing can narrow; the conjunct stays residual.

## Acceptance Criteria

- Pushdown emits the alternation for property-resolved, except in the default
  cases above, where it pushes nothing.
- Differential tests over a fixture corpus with entries on both sides of the
  default: org-ql's whole-corpus answer file-by-file against the narrowed
  answer, superset asserted; fixtures include a follower whose file has no
  local NAME line at all.
- Mutation evidence: dropping the PROTOTYPE arm of the alternation, and
  pushing despite the default exception, each fail a named test.

#+begin_example
Add a ripgrep prefilter backend so corpus scopes need no database.

Measured on 2026-08-19 against the real corpus (~/org, 3,634 non-archive .org
files, 33 MB). Full log: prefilter-alternatives.md in the SDD workspace.

## Why

The database is only a candidate-file narrower — evaluation is org-ql and always
was. But today it is the *only* narrower, so the three unbounded scopes
(`active`, `all`, a directory) hard-error without a reachable PostgreSQL. Live
evaluation is not a real fallback: no prefilter at all costs 45.98s, 885 MB peak
RSS, and 3,640 open buffers for one query.

ripgrep does the same narrowing from the live files:

| path | files opened | wall clock | result |
|---|---|---|---|
| no prefilter | 3,634 | 45.98s | 764 matches |
| rg prefilter + org-ql | 309 | 3.90s (rg 0.13s) | 764 matches |

Same 764 matches from 309 files as from 3,634 — an empirical superset check on
real data, which the database path has never had (its 20 differential tests
still cannot run for want of a reachable DB).

## Two correctness advantages over the DB, not just setup

1. No staleness window. README §"The database prefilter" concedes a file that
,   *newly* satisfies a pushed conjunct since the last `org db sync` is missed
   until the next sync — a false negative. rg reads live bytes.
2. No second parser to diverge. Honest-limitation #2 (`:PROP+:` continuation
   line makes org-jw discard the whole drawer) cannot arise when the prefilter
   matches the same bytes org-ql reads.

## Shape of the work

`org-agents--pushdown-fns` is already backend-agnostic — it emits abstract
superset-safe conjuncts, and only the closing `prin1-to-string` in
`org-agents--skeleton` is CLI-specific. So:

- Change `--skeleton` to return the conjunct sexp; let each backend serialize.
  The CLI bridge keeps its `prin1`.
- New backend emits one rg pattern per conjunct, intersecting per-conjunct file
  sets for `and` and unioning for `or`:
  `(property NAME)` → `^[ \t]*:NAME:`;
  `(property NAME VAL)` → same plus `regexp-quote`d value;
  `(scheduled/deadline/closed …)` → stamp existence only;
  `(heading "lit")` → `^\*+ .*lit`; `(path DIR)` → rg `--glob`.
- A defcustom choosing the backend, defaulting to rg when `rg` is on PATH.

rg cannot compare dates, so planning conjuncts push as bare stamp existence.
Measurement retires that worry: `SCHEDULED:` occurs in 186 of 3,633 files and
`DEADLINE:` in 46 — 95–99% narrowing from existence alone.

## Acceptance Criteria

- A corpus-scope agent updates with no `org db` configured at all.
- A test asserts the rg-narrowed candidate set is a superset of the files
  org-ql's own answer came from, over a fixture corpus (the check the DB path
  cannot run).
- README's prefilter section documents both backends and the staleness
  difference between them.
